# Changelog

All notable changes to Loom are listed here, newest first. Versions follow [Semantic Versioning](https://semver.org). While Loom is on 0.x, a minor version may include breaking changes.

## Unreleased

- 96 more bundled themes, from the color schemes at [TerminalColors](https://terminalcolors.com/): Apprentice, Ayu Mirage, Cobalt2, Deus, Dracula, GitHub, the Gruvbox contrast variants, Iceberg, Jellybeans, Kanagawa, Lucario, Miasma, Moonfly, Night Owl, Nightfly, Nightfox, Noctis, Nord, Nordic, One, One Half, Panda, Posterpole, Rosé Pine, Seoul256, Shades of Purple, Sonokai, Srcery, Tender, Tokyo Night Day, Tomorrow, and Zenbones, with their variants. Pick one with `ctrl-k ctrl-t`; terminals take their colors from it.
- The protocol version is now 10. Agents and clients of 0.2.0 (protocol 9) cannot connect to these, so upgrade both; running agents keep their old version until you restart them. Opening a session now loads only its latest 50 messages and tool calls, sent in a few large messages instead of one message per event, and the client loads earlier ones as you scroll to the top. Long sessions open much faster, and opening one through a relay no longer exceeds the relay's message rate limit, which dropped the agent's link to the relay.
- The protocol version is now 13. Agents and clients built before it (protocol 10 to 12) cannot connect to these, so upgrade both; running agents keep their old version until you restart them.
- The desktop app no longer closes a session's conversation tab. Close a session with **Close session** in its menu in the agents panel or **session: close** in the command palette instead; closing its other tabs keeps it open.
- Terminals are shared by an agent's clients. Every client shows the agent's terminals, also those that another client opened: the desktop as tabs in the agent's active session, which say where a terminal is open, and the Android app in its terminal menu. A terminal is open on one client at a time. A terminal that is open elsewhere shows dimmed with a **Take over** button, which moves it to this client with its recent output (up to 128 KiB), which the agent now keeps; the other client can take it back the same way. The desktop does not close the tab of a terminal that is open elsewhere. After a lost connection, a client takes back only the terminals that no other client took meanwhile.
- The notes belong to the agent now, not to each session: all sessions of an agent share one set of notes about the work in its workspace, and deleting a session keeps them. The client's **Notes** tab and the Android app's notes screen show the agent's notes. On its first start, an upgraded agent merges the notes of its sessions into its notes, each under a heading with the session's title. `notes_write` refuses to replace notes that another session changed since this one last read them. See [Notes and tasks](README.md#notes-and-tasks).
- The `edit` tool takes a patch in unified diff format instead of text replacements, and one patch can change several files, create them (`--- /dev/null`), delete them (`+++ /dev/null`), and move them. Hunks are placed by their context lines, with line numbers only to choose between several matches, and nothing changes unless the whole patch applies. `notes_edit` takes a patch of the notes the same way. Tool calls from earlier versions still show as before.
- You can send messages while a turn runs. `enter` queues a message to start the next turn when the running one completes; `ctrl-enter` or the **Steer** button puts it into the running turn after its current tool calls. Waiting messages are listed above the prompt box, where you can take one back to edit it, and stay waiting after a turn you stop. See [Messages while a turn runs](README.md#messages-while-a-turn-runs).
- An Android app, in `android/`, for agents you reach through a relay. Pair it with a host by scanning the QR code of `loom-agent pair` or pasting its link; it then lists every session of the host's agents, where you can start, rename, archive, and delete them (also starting a session in another directory of the host, which gets an agent of its own), and in a session you can follow the conversation, approve or deny tool calls, send messages, stop a turn, change the model, the reasoning effort, and the default for tool calls that no policy rule matches, compact or clear the conversation, edit the notes and tasks, see the workspace's uncommitted changes and the files the session changed with their diffs, browse the agent's workspace and read its files, with files and diffs highlighted for their language, and open terminals on the agent's host, with a row of extra keys, that survive a dropped link. Its **Font** screen sets the text size, the size of the text in tool call and reasoning blocks, and the fonts of text and of code (JetBrains Mono by default), from the system's fonts or any of Google Fonts, which you can search by name and filter by category and script, each with an optional fallback font for the characters it does not have, such as Hangul. It reconnects by itself, checks its links at once when it comes back on screen or the phone changes networks, follows an agent that was restarted, and says whether the app or the agent needs an update when their protocols differ. Built with a Firebase project, it shows notifications when a tool call waits for approval and when a turn finishes or fails, also while it is closed, and tapping one opens the session. It needs Android 17 (API 37) or newer on arm64, and you build it yourself for now (CI builds a debug APK of every change); see [The Android app](README.md#the-android-app).
- Notifications for the Android app. An agent with a relay seals each one for every paired phone that asked for them, with the keys from pairing, and its relay sends it through Firebase Cloud Messaging, so Google sees only ciphertext. The relay needs a service account key of the app's Firebase project, set as `push.fcm.service_account` in `relay.yaml`, and its metrics count the notifications it sent, could not send, and dropped. Relays now speak version 2 of the relay protocol and still take agents of version 1; an upgraded agent falls back to version 1, without notifications, when its relay is older.
- Images (PNG, JPEG, WebP, GIF, BMP, TIFF, and icons) and PDF files of up to 64 MB open in a viewer instead of as text, in the desktop app and in the Android app. The desktop viewer zooms with its toolbar, fits the image or the page width, and draws a PDF file's pages as they scroll into view; the Android viewer zooms by pinching. Agents now send files in chunks through a relay too, so downloads from the desktop app also work through a relay.
- A relay slows down connections that send more messages than `limits.messages_per_second` allows, after the `limits.burst`, instead of closing them, so a large transfer no longer cuts every connection that shares its IP address (as all of them do behind a Cloudflare Tunnel). `loom_relay_rate_limited_total` counts the slowed messages and the refused connections.
- `loom-agent config check` fails when the configuration file does not exist, instead of printing `ok` for the defaults the agent would use, so a mistyped `--config` path no longer looks valid.

## 0.2.0

- Each session has notes and a task list, which stay when the conversation is compacted or cleared. The notes are a text scratchpad for the agent's findings and decisions; the agent uses them through the new `notes_read`, `notes_edit`, and `notes_write` tools, and you can read and edit them in the client's new **Notes** tab. The task list is the plan of the work, as tasks that are created, in progress, or done; the agent uses it through the new `tasks_read` and `tasks_update` tools, and you can add, edit, check off, and remove tasks in the new **Tasks** tab, which shows each task's number (`#3`) as the agent refers to it. `tools.notes.max_bytes` and `tools.tasks.max_items` in `agent.yaml` limit their size (64 KiB and 100 tasks by default). See [Notes and tasks](README.md#notes-and-tasks).
- The protocol version is now 9. Agents and clients of 0.1.0 (protocol 6) cannot connect to these, so upgrade both. Running agents keep their old version until you restart them.
- `loom-agent reload --workspace <dir> | --instance <id> | --all`, and **Reload configuration** in an agent's menu in the Agents panel, make running agents read `agent.yaml` again and say whether they reloaded it, found it unchanged, or rejected it. The client now shows configuration notices as sentences, such as which sections need a restart or why a file was rejected, instead of their raw form. See [Reloading the configuration](README.md#reloading-the-configuration).
- `limits.max_rounds_per_turn` in `agent.yaml` sets the most model calls the agent makes for one message (200 by default, as before; `0` for no limit). It was fixed at 200 before. A config reload applies it at once, also to a turn that is running.
- New keys for tabs, which also work in terminals: `ctrl-tab` / `ctrl-shift-tab` for the next / previous tab, `alt-1` to `alt-8` for that tab and `alt-9` for the last one, and `ctrl-shift-pagedown` / `ctrl-shift-pageup` to move a tab right / left. `ctrl-shift-b` shows the Agents panel, `ctrl-shift-n` the Notes panel, and `ctrl-shift-t` the Tasks panel.
- Releases include `loom-agent` and `loom-relay` for arm64 Linux (`aarch64-unknown-linux-musl`), statically linked like the x86-64 ones, and `scripts/install.sh` picks the archive for the host's architecture. The GUI is still x86-64 only.
